# ML Prediction Contract

## 1. Purpose

This document defines the interface between the Student Performance
Prediction ML component and the backend PredictionService.

The ML component is responsible only for numerical academic performance
prediction.

Natural-language explanations and personalized roadmap generation are
handled separately by the AI/LLM layer.

---

## 2. ML Boundary

Backend
    |
    v
PredictionProvider
    |
    v
ML Model
    |
    v
PredictionResult

The ML model must not directly access:

- PostgreSQL
- FastAPI application/database logic
- JWT/authentication
- React frontend
- OpenAI
- Gemini
- MCP
- Qdrant

The backend communicates with the ML component through the prediction API.

---

## 3. Production Model

The current production model is:

- model_version: E46_V1
- feature_set_version: FS_E46_V1
- algorithm: GradientBoostingRegressor
- preprocessing: B_domain_aware_indicator
- removed feature: F010_PREVIOUS_SGPA
- production feature count: 11
- target: FINAL_EXAM_PERFORMANCE_PCT

E46_V1 was selected using the project's validation protocol and evaluated
on the locked final-test period before production fitting.

---

## 4. Model Input

The E46_V1 production model accepts exactly the following 11 engineered
academic features:

- F001_ATTENDANCE_PCT
- F002_ASSESSMENT_AVG_PCT
- F003_ASSIGNMENT_AVG_PCT
- F004_ASSIGNMENT_COMPLETION_RATE
- F005_QUIZ_AVG_PCT
- F006_QUIZ_COMPLETION_RATE
- F007_LAB_AVG_PCT
- F008_INTERNAL_ASSESSMENT_PCT
- F009_PREVIOUS_SEM_PCT
- F011_BACKLOG_COUNT
- F017_ASSESSMENT_PARTICIPATION_RATE

F010_PREVIOUS_SGPA is explicitly excluded from E46_V1.

F012, F015, F018, F019 and F020 are not part of the E46_V1 production
feature set.

The backend must prepare validated engineered feature values before calling
the ML prediction service.

Missing values may be supplied where permitted by the preprocessing
pipeline. The production model performs its defined missing-value handling.

---

## 5. Target

The sole ML target is:

FINAL_EXAM_PERFORMANCE_PCT

The target is normalized to the range 0-100.

Formula:

FINAL_EXAM_PERFORMANCE_PCT =
(final examination obtained marks /
 final examination maximum marks) * 100

Final examination marks must never be included as input features.

---

## 6. Maximum Marks

The model predicts examination percentage rather than assuming a fixed
final examination maximum of 100.

After prediction:

predicted_marks =
(predicted_percentage / 100) * final_exam_maximum_marks

Examples:

84% with maximum 50 -> 42/50

84% with maximum 20 -> 16.8/20

84% with maximum 80 -> 67.2/80

84% with maximum 100 -> 84/100

The backend must provide the actual final_exam_max_marks when requesting
a prediction.

---

## 7. Data Authority

Academic input data may originate from:

- TEACHER_VERIFIED
- STUDENT_ENTERED
- SYSTEM_DERIVED

Teacher-verified data has higher authority than temporary student-entered
data.

Rejected or invalid teacher submissions must not be treated as verified
input.

The ML model itself does not determine whether data is authoritative.
The backend is responsible for preparing the appropriate data and
identifying its status.

---

## 8. Prediction Cutoff

Every prediction must have a prediction timestamp/cutoff.

Only information available at or before the cutoff may be used.

Future:

- assessments
- attendance
- assignments
- quizzes
- roadmap events
- verification results

must not enter the prediction features.

The backend is responsible for enforcing the data cutoff before requesting
a prediction.

---

## 9. Prediction Request

The prediction API is:

POST /api/v1/predictions/run

The request must contain the production feature values and:

- final_exam_max_marks
- prediction timestamp/cutoff where required by the API
- data status
- verified-data status where applicable

The exact JSON schema exposed by the running FastAPI application is the
authoritative API schema.

---

## 10. Prediction Result

The production ML API returns:

- predicted_percentage
- predicted_marks
- final_exam_max_marks
- model_version
- feature_set_version
- prediction_timestamp
- data_status
- verified_data_used

The production E46_V1 model currently does not implement:

- grade_category
- risk_level
- confidence_or_uncertainty

These fields must not be interpreted as model-generated values unless a
future model/API version explicitly implements them.

---

## 11. Grade Category

Grade categories are an application-level feature and are not currently
generated by E46_V1.

If required, categories such as:

- EXCELLENT
- GOOD
- BAD
- WORSE

may be implemented later using configurable thresholds.

Thresholds must not be permanently hardcoded inside the ML model without
an approved project specification.

---

## 12. Risk Level

Risk level is not currently generated by E46_V1.

If required, the application may derive a configurable risk classification,
for example:

- LOW
- MODERATE
- HIGH

The thresholds must be defined separately from the trained ML model.

---

## 13. Confidence and Uncertainty

E46_V1 currently does not provide a calibrated confidence or uncertainty
estimate.

The field must not be presented as a statistically calibrated confidence
value unless a future model version implements and validates such a method.

---

## 14. Model Versioning

Every prediction must identify the model that generated it.

Current production model:

model_version = E46_V1

Current production feature set:

feature_set_version = FS_E46_V1

Dataset version should also be tracked by the training/evaluation workflow
when a formal dataset version is defined.

---

## 15. Prediction History

The backend system should preserve previous predictions.

A new prediction must not overwrite historical predictions without retaining
the previous record.

This allows:

- performance trend graphs
- prediction variation analysis
- model comparison
- auditing
- teacher analytics

Prediction history is a backend responsibility, not a responsibility of the
ML model artifact.

---

## 16. Student Temporary Prediction

If teacher-verified data is incomplete, the student may temporarily enter
missing academic values where permitted by the application.

Such a prediction must be identifiable as temporary/unverified.

When teacher-verified values become available, the backend may request a new
prediction using the authoritative data.

The new prediction must not erase the historical temporary prediction.

---

## 17. Model Selection

E46_V1 uses:

- Gradient Boosting Regressor
- domain-aware missing-value handling with missingness indicators
- F010_PREVIOUS_SGPA removed from the production feature set

The model was selected experimentally using the project's validation
protocol.

No pretrained student-performance model or external prediction API is used.

The production model was trained using the project dataset.

---

## 18. LLM Separation

The ML model is responsible for numerical academic prediction.

The LLM/AI Gateway may use the prediction result to:

- explain prediction factors
- summarize weak areas
- generate personalized learning roadmaps
- recommend learning resources

The LLM must not replace the academic prediction model.

The LLM must not directly modify the numerical prediction produced by the
ML model.

---

## 19. Backend Integration

The backend PredictionService is responsible for:

1. authentication/authorization
2. retrieving permitted academic data
3. preparing validated feature input
4. enforcing the prediction cutoff
5. calling the ML PredictionProvider
6. storing PredictionResult
7. returning the result to the requesting client

The ML component is not responsible for:

- authentication
- authorization
- database access
- student account management
- frontend rendering
- prediction history storage
- natural-language generation

---

The production model artifact is:
